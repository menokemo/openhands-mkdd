# MKDD — نظام تشغيل شركة سوفتوير بالذكاء الاصطناعي

> **آخر مراجعة شاملة:** 2026-08-30. هذا الملف مرجع حي — يُحدَّث كل ما يتغير شيء جوهري في المشروع، لا لقطة زمنية ثابتة. للسجل الزمني الكامل لكل تغيير، راجع `CHANGELOG.md`. لأي مشكلة تُكتشف وحلها بالتفصيل، راجع `BUGS_AND_FIXES.md`.

## 1. إيه هو MKDD؟

**MKDD** نظام تشغيل لشركة سوفتوير مبنية بالكامل على وكلاء ذكاء اصطناعي، مبني فوق **OpenHands Agent Canvas** (محرك تنفيذ الوكلاء نفسه — بيوفّر المحادثات، تشغيل الأوامر، تعديل الملفات، إلخ).

**الفكرة الأساسية:** بدل محادثة عامة واحدة تسأل فيها الذكاء الاصطناعي "اعمل لي كذا"، MKDD بيقسّم الشغل على **14 موظف افتراضي** بأدوار محددة (Product Manager, Architect, Implementation Engineer, QA...)، كل واحد بهوية ثابتة وتعليمات واضحة، ضمن **سير عمل إجباري بـ4 بوابات** (Requirements → UI/UX → Architecture → Production)، مع قواعد حوكمة صارمة (مراجعات إجبارية، لا نشر بدون موافقة صريحة من المالك).

**المبدأ المعماري الحاكم:**
```
GitHub  = مصدر الحقيقة للكود
OpenHands = محرك التنفيذ (المحادثات، الأدوات، بيئة العمل)
MKDD    = طبقة الهوية، سير العمل، والحوكمة
```

---

## 2. ليه المشروع ده موجود

OpenHands لوحده أداة قوية جدًا، لكنها عامة — "ابدأ محادثة واسأل عن أي حاجة". MKDD بيضيف طبقة أعلى بتحوّلها لتجربة "شركة سوفتوير حقيقية":

- موظفين بهوية ثابتة (مش جلسات مجهولة).
- سير عمل واضح بمراحل وموافقات.
- بوابات إجبارية (مفيش برمجة قبل اعتماد المعمارية، مفيش نشر بدون موافقة الإنتاج).
- مراجعات إجبارية (QA، اختبارات آلية، مراجعة كود، مراجعة أمان) قبل أي اعتماد نهائي.
- محادثة منفصلة لكل موظف في كل مشروع — عزل كامل، مفيش "جروب شات" جماعي.
- لوحة تحكم واحدة (Project Home) تعرض حالة كل شيء — مين شغال، على إيه، إيه اللي خلص، وإيه اللي عالق.

## 5. سير عمل الشركة (4 بوابات إجبارية)

1. **Requirements** — لا برمجة قبل اعتماد هذه البوابة.
2. **UI/UX**
3. **Architecture** — لا برمجة قبل اعتماد هذه البوابة تحديدًا.
4. **Production** — لا نشر إنتاجي بدون موافقة صريحة من المالك.

### قواعد إجبارية (مش اقتراحات)
- مراجعة QA، مراجعة اختبارات آلية، مراجعة كود، مراجعة أمان — كلها إجبارية قبل اعتماد بوابة Production.
- المراجع لا يصلح ملاحظته بنفسه — نفس المراجع يتحقق من الإصلاح لاحقًا.
- لا دمج (merge) بدون موافقة صريحة من المالك.
- عوائق مفتوحة (blockers) تمنع تقدم البوابة.
- حالة سير العمل محفوظة (persisted) بشكل منفصل تمامًا عن تاريخ محادثات OpenHands — راجع `server/workflow-state.mjs`.

## 6. نظام التقارير بين الموظفين

أي موظف يقدر يسجّل ملاحظة حقيقية عن شغل موظف آخر (مش بس مراجعو الجودة الأربعة) — عبر استدعاء API حقيقي `/api/workflow/reports`، مربوطة ببوابة سير العمل ذات الصلة.

**تسليم تلقائي (بدون تدخل المالك):** لحظة تسجيل التقرير، الخادم يبني رسالة واضحة تلقائيًا (اسم المُرسِل، العنوان، التفاصيل، أمر رد جاهز بمعرّف التقرير الحقيقي) ويسلّمها فورًا لمحادثة الموظف المستلم — يبدأ الشغل عليها مباشرة، بدون انتظار المالك يوصّلها يدويًا. لما الموظف المستلم يرد، حالة التقرير تتحدّث تلقائيًا. تفاصيل التصميم الكاملة في `BUGS_AND_FIXES.md #154`.

## 7. المحادثة الحية والوقت الحقيقي

الدردشة تعتمد على مزيج REST + WebSocket:
- تحميل أولي عبر REST.
- أحداث حية عبر WebSocket (`server/lib/ws-bridge.mjs`) مع إعادة اتصال تلقائية عند الانقطاع.
- رسالة تفاؤلية فورية عند الإرسال (تظهر قبل تأكيد الخادم).
- دمج الأحداث بمعرّف فريد (لا استبدال كامل للتاريخ عند كل تحديث).

**مبدأ الاستقرار الأساسي:** بيانات مؤكَّدة لا تختفي أبدًا بسبب فشل مؤقت في طلب تحديث — الواجهة تحتفظ بآخر بيانات صحيحة معروفة وتحدّث في الخلفية، ولا تعرض حالة "تحميل" كاملة إلا لو معندهاش أي بيانات مؤكَّدة من الأساس.

## 8. المعاينة الحية للتطبيقات الحقيقية

أي تطبيق حقيقي يبنيه موظف (زي كيرلس) بيحصل على **بورت مخصص دائم** من نطاق `4001-4020` (راجع `server/lib/live-port-registry.mjs`)، بتمرير خام 100% بدون أي تعديل محتوى أو إعادة كتابة مسارات — فئة كاملة من مشاكل "المسار المطلق اللي بيفلت من إعادة الكتابة" أصبحت مستحيلة بنيويًا بهذا التصميم.

## 9. نظام المراقبة الاستباقي وصحة النظام

بعد جلسة تطوير طويلة اكتُشفت فيها مشاكل استقرار حقيقية (انهيار السيرفر بالكامل، مشكلة ملكية Git تكسر كل محادثة جديدة، انقطاعات اشتراك LLM) كان لازم اكتشافها يدويًا كل مرة، بُني نظام مراقبة كامل يكتشف هذه الفئة من المشاكل **تلقائيًا وقبل** ما تؤثر على المالك.

### الفحوصات السبعة (`deploy/health-check.sh`)
1. حالة الحاويات (`mkdd-ui` و`agent-canvas` فعليًا شغالين).
2. استجابة `/api/health` بدون مصادقة.
3. استجابة `/ready` بتاعة OpenHands نفسها.
4. سلامة ملكية Git داخل `agent-canvas` (استثناء `safe.directory`).
5. جدولة نظام النشر التلقائي نفسه (`mkdd-auto-deploy.timer` عنده موعد تشغيل حقيقي قادم).
6. فحص عميق اختياري: فتح محادثة حقيقية لموظف حقيقي (يكتشف تعليق الخادم/WebSocket).
7. صحة اشتراكات LLM — **عام تمامًا، بدون تثبيت أي اسم مزوّد أو موديل في الكود** — يكتشف الملفات الشخصية المُسجَّلة فعليًا وقت التشغيل، ويفحص فقط ما هو قائم على اشتراك.

### الآلية
```
كل 5 دقائق (mkdd-health-check.timer)
    ↓
health-check.sh يشغّل الفحوصات السبعة
    ↓
يكتب النتيجة لملف حالة مشترك (mkdd-data/health-status.json)
يسجّل أي "تحوّل" حالة (سليم↔فاشل) في سجل تاريخي محدود الحجم (health-history.jsonl)
    ↓
عند أي فشل → تنبيه فوري (Push Notification) للمالك عبر /api/internal/alert
```

**الشاشة:** من سايدبار MKDD → "صحة النظام" — تبويب "الحالة الحية" (نتيجة كل فحص الآن) وتبويب "السجل" (تاريخ كل مرة اتغيّرت فيها حالة أي فحص).

**تفعيل الفحص العميق (اختياري، موصى به):** إضافة `MKDD_HEALTH_CHECK_PROJECT`, `MKDD_HEALTH_CHECK_EMPLOYEE_ID`, `MKDD_HEALTH_CHECK_EMPLOYEE_NAME` في ملف `.env` الفعلي على الخادم (بمشروع/موظف حقيقيين موجودين فعلاً).

تفاصيل التصميم والاختبار الكاملة في `BUGS_AND_FIXES.md #157` حتى `#163`.

**الاستئناف التلقائي:** بالإضافة للمراقبة، النظام يتخذ إجراءً فعليًا عند اكتشاف محادثة توقفت بسبب حد استخدام حقيقي انتهى وقته — يرسل رسالة استئناف تلقائيًا (تعتمد على معيار استمرارية العمل الموثَّق مسبقًا لدى كل موظف)، مع تنبيه فوري للمالك. يغطي كل الموظفين، بدون حد زمني على "آخر نشاط" (بما أن حد الاستخدام قد يستغرق أيامًا لإعادة التعيين). تفاصيل التصميم الكاملة في `BUGS_AND_FIXES.md #175`.

## 10. النشر التلقائي (Auto-Deploy)

أي commit يوصل لفرع `main` على GitHub، بيتنزل ويتبني ويتشغّل تلقائيًا خلال ثوانٍ، مع rollback تلقائي عند الفشل — راجع `deploy/README.md` للتفاصيل الكاملة (المعمارية، التركيب، المراقبة).

**عزل كامل عن الإنتاج:** بيئة الـstaging (اللي عليها النشر التلقائي شغال) معزولة تمامًا عن أي حاوية إنتاجية شغالة — بورتات، أسماء حاويات، أسماء صور، وVolumes منفصلة تمامًا. لا تعارض ممكن يحصل حتى لو الاثنين شغالين في نفس اللحظة على نفس الخادم.

## 11. الأمان — المبادئ الحاكمة

- **مفتاح جلسة OpenHands لا يصل للمتصفح أبدًا** — يبقى Server-side فقط.
- **مفتاح خدمة داخلي مشترك** (`X-Internal-Service-Key`) لتفويض استدعاءات موثوقة بدون جلسة متصفح (موظف بيسجّل تقرير عبر `curl`، أو سكريبت المراقبة الآلي) — نطاق ضيّق ومحدود عمدًا لمسارات `/api/workflow/*` و`/api/internal/*` فقط، لا يمنح وصولًا لأي endpoint آخر مهما كان.
- **إعدادات حساسة (إعادة تشغيل الحاوية، إلخ) مقيَّدة على الوصول المحلي فقط** — فحص حقيقي على مستوى الخادم (`Host` header)، لا مجرد إخفاء زر في الواجهة.
- **لا رسائل مباشرة بين الموظفين** — موظف لا يقدر يبدأ أو يكتب في محادثة موظف آخر مباشرة؛ فقط MKDD نفسها (عبر نظام التقارير) تملك هذه القدرة.
- **بيانات هوية العميل (`employeeId`/`employeeName`) غير موثَّقة بمصادقة كاملة بعد** — دَين تقني معروف، محتاج طبقة هوية مستخدم حقيقية لاحقًا (راجع القسم 13).
- **تطبيع آمن للأحداث** — الواجهة تعرض نشاطًا تشغيليًا آمنًا (اسم الأداة، ملخص الإجراء، حالة الخطأ) ولا تُسرِّب سلسلة التفكير الداخلية للنموذج أبدًا.

---

## 12. مبادئ سلامة البيانات

- **لا بيانات مُختلَقة أبدًا** — خطة العمل (Work Plan) مُستخرَجة من أحداث `task_tracker` الحقيقية، والتكلفة من إحصائيات المحادثة الفعلية. لو المقياس غير متاح، الواجهة تعرض "غير متاح"، لا رقمًا مُختلَقًا.
- **GitHub مصدر الحقيقة للكود** دائمًا.
- **حالة سير العمل تحت سيطرة MKDD الصريحة**، منفصلة عن تاريخ محادثات OpenHands.

---

## 13. الحالة الحالية — إيه اللي لسه ناقص

- **مصادقة مستخدم حقيقية متعددة المستخدمين** — لسه غير موجودة؛ حساب مالك واحد فقط حاليًا.
- **آلية اكتشاف مفتاح الجلسة عبر `/proc`** — دَين تقني معروف، يحتاج آلية أسرار مدعومة رسميًا بدلًا منه.
- **تنبيه تجاوز الميزانية/التكلفة** — التكلفة تُعرَض لكل موظف، لكن مفيش تنبيه تلقائي عند تجاوز حد معين حاليًا.
- **نسخ احتياطي شامل** — `backup-mkdd-data.sh` تحفظ بيانات MKDD نفسها، لكن تاريخ محادثات الموظفين (على Volume خاص بـOpenHands) ليس جزءًا من النسخ الاحتياطي حاليًا.
- **PWA، CI/CD، تغطية اختبارات أشمل** — مؤجلة لحد ما الأساسيات تستقر بالكامل.

## 14. أول خطوة لأي حد جديد

```bash
git clone https://github.com/menokemo/openhands-mkdd.git
cd openhands-mkdd
./setup.sh
```

هذا يبني ويشغّل كل شيء (Agent Canvas + MKDD UI) بالإعدادات الافتراضية:
- MKDD UI: `http://localhost:8787`
- Agent Canvas: `http://localhost:8000` / `http://localhost:3000`

للتطوير على الـ backend فقط:
```bash
cd mkdd-ui
npm ci
npm test       # الاختبارات الآلية
npm run build  # التحقق من صحة TypeScript والبناء
```

**لتركيب نظام النشر التلقائي + المراقبة على خادم جديد (خطوة واحدة، مرة واحدة):** راجع `deploy/README.md`.

## 16. أين أدوّر على تفاصيل أعمق؟

- **"ليه اتصلحت مشكلة معينة، وإزاي؟"** → `BUGS_AND_FIXES.md` (كل بند مرقَّم، مُفصَّل، مع طريقة التحقق الفعلية).

- **"إيه المبادئ الهندسية الثابتة اللي كل ميزة جديدة لازم تلتزم بيها؟"** → `ENGINEERING_PRINCIPLES.md`.
- **"مرجع سريع لأي حد جديد + سجل تاريخي للتطور؟"** → `PROJECT_SUMMARY.md`.
